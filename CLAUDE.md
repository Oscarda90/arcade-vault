# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Arcade Vault — plataforma para jugar online y competir por puntaje. UI y textos en español; tema neón/pixel portado de `references/templates/`.

Estado actual (SPEC 01–09): landing, biblioteca, ficha de juego, reproductor, auth real con Supabase, Salón de la Fama, Acerca de con contacto vía Resend, y **4 juegos jugables** con leaderboard real: `rocas` (Asteroids), `caida` (Tetris), `bloque-buster` (Arkanoid), `serpentina` (Snake original). El resto del catálogo son juegos mock (`playable = false`, "PARTIDA DEMO · NO PUNTÚA").

No test runner is configured. Adding one is a decision to raise with the user, not to assume. Verificación = `npm run lint` + `npm run build` + probar en navegador.

## Commands

```bash
npm run dev       # next dev (Turbopack)
npm run build     # next build
npm run lint      # eslint (flat config)
npm run db:push   # supabase db push --remote (aplica supabase/migrations/)
npm run db:types  # regenera lib/supabase/database.types.ts desde el proyecto remoto
```

Env vars: ver `.env.example` (copiar a `.env.local`). Resend: `RESEND_API_KEY`, `CONTACT_TO_EMAIL`, `CONTACT_FROM_EMAIL` (servidor). Supabase: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `SITE_URL`. Nunca usar la service_role key.

## Workflow: Spec Driven Design

- Todo cambio de producto pasa por un spec en `specs/NN-slug.md` (header: Status `Borrador|Aprobado|Implementado`, Depends on, Date, Objective). Leer los specs previos relevantes antes de tocar un área: fijan convenciones (SPEC 03 Server Actions/secretos, 04 Supabase/auth, 05 motores, 06 caché/leaderboard, 07 HUD genérico).
- Rama por spec: `spec-NN-slug`, merge vía PR a `main`. `specs/.spec-config.yml` → `AutoCreateBranch: true`.
- Al terminar la implementación, actualizar el Status del spec a `Implementado`.

## Skills

- `/spec` — redacta un spec nuevo (plantilla `.claude/skills/spec/template.md`). De [Klerith/fernando-skills](https://github.com/Klerith/fernando-skills), registrado en `skills-lock.json`; copia también en `.agents/skills/`.

No escribe código; luego `/spec-impl`. Refs: `references/contrato-integracion.md`, `references/portar-referencia.md`, plantilla en `assets/plantilla-spec.md`.

## MCP

`.mcp.json` configura el MCP de Supabase (proyecto remoto). Usarlo para inspeccionar tablas, logs y advisors; los cambios de esquema van siempre como migración en `supabase/migrations/` (no SQL suelto en remoto).

## Stack / architecture notes

- **Next.js 16.4.5 + React 19.3, App Router**, TypeScript strict. This Next major has breaking changes relative to common training data: consult `node_modules/next/dist/docs/` (notably `01-app/`) before writing framework code. `AGENTS.md` carries this same rule and is regenerated by `next dev` — commit its changes alongside your work rather than reverting them.
- **`next.config.ts` opts into pre-stable features**: `cacheComponents`, `partialPrefetching`, `experimental.agentFeedback`. These change caching/prefetch semantics — read the corresponding docs before adding data fetching or route segments.
- **Tailwind CSS v4 sin preflight**, no `tailwind.config`. `app/globals.css` importa solo theme + utilities; tokens del tema (`--bg`, `--cyan`, `--magenta`, `--pixel`, …) en `:root` y expuestos vía `@theme inline`. Los estilos del template viven como clases en `@layer components` (p. ej. `cover-*`, `.hud-stat`). Procesado por `@tailwindcss/turbopack` (regla Turbopack en `next.config.ts`).
- Route types come from Next's generated `.next/types` (e.g. `LayoutProps<"/">` is global, not imported) — regenerate on `dev`/`build`.
- Import alias: `@/*` → repo root.
- `references/` = material fuente (templates JSX/CSS del diseño, `started-games/` con juegos JS de referencia, `source-assets/`). No es código de la app; no importarlo.

### Rutas (`app/`)

`/` landing · `/biblioteca` catálogo con filtros · `/juegos/[id]` ficha + leaderboard · `/juegos/[id]/jugar` reproductor · `/salon` Salón de la Fama · `/auth` login/registro · `/auth/confirm` route handler de confirmación de correo · `/acerca` about + contacto. `proxy.ts` (antes middleware) refresca la sesión Supabase en cada request vía `lib/supabase/proxy.ts`.

### Supabase

- Clientes: `lib/supabase/server.ts` (con cookies; Server Components/Actions/Route Handlers, uno por request), `lib/supabase/client.ts` (navegador), `lib/supabase/public.ts` (anon sin cookies, solo lecturas públicas dentro de `"use cache"`). Falta de env → `SupabaseConfigError`.
- Esquema (migraciones): `profiles` (username único, creado por trigger `handle_new_user` al registrarse; sin políticas de escritura), `games` (catálogo, `playable`, `sort_order`), `scores` (insert solo propio y en juegos `playable`; check `1..SCORE_MAX`), vistas `leaderboard` y `game_stats`. Tras cambiar esquema: `db:push` + `db:types`.
- Auth: email + contraseña; validación compartida en `lib/auth.ts` (username `^[A-Z0-9_]{3,10}$` en mayúsculas). Server Actions en `app/auth/actions.ts`. Sesión cliente: `lib/session.tsx` (`useSession`).

### Datos y caché

- `lib/games.ts`: solo tipos (`Game`, `ScoreRow`), `SCORE_MAX`, helpers. Los datos se leen en `lib/data/games.ts` (`server-only`, `"use cache"` + `cacheTag("games" | "scores")`).
- Mutaciones = Server Actions que nunca lanzan y devuelven `{ ok } | { ok: false, error: Code }`; invalidan con `updateTag` (p. ej. `submitScore` en `app/juegos/actions.ts` → `updateTag("scores")`).
- Contacto: `app/acerca/actions.ts` + validación en `lib/contact.ts` (escapar HTML), envío con Resend.

### Motores de juego (`lib/engines/`)

- Contrato en `types.ts`: `EngineFactory(canvas, callbacks) → GameEngine` (`pause/resume/restart/end/destroy`); callbacks `onStats` (solo al cambiar), `onStateChange`, `onGameOver`. `EngineStats`: `score`, `lives?`, `level?`, `extras?` (stats propias del HUD).
- `registry.ts`: mapa `id → { factory, startLabel, controls, initialStats }`. El id coincide con `public.games.id`.
- `components/game-canvas.tsx` monta el motor en `<canvas>`; `components/game-player.tsx` pinta HUD/overlay/pausa/modal genéricos desde el registro y llama a `submitScore`. Un juego nuevo no debería tocar estos componentes ni `types.ts`.
- Añadir juego: `/nuevo-juego` → spec → motor en `lib/engines/<juego>.ts` + entrada en registry + migración que pone `playable = true` en su fila.
